# tree-sitter-texinfo

A tree-sitter grammar for GNU Texinfo. The reference for correct behaviour is
`texi2any` (Texinfo 7.3), whose command classes come from
`tta/data/command_data.txt` in the Texinfo sources. `TODO.md` tracks coverage.

## Environment

- The Nix dev shell (`flake.nix`) provides tree-sitter, Node, clang/clangd,
  texinfo and Python with py-tree-sitter. direnv loads it automatically; after
  changing `flake.nix`, run commands through `direnv exec .` until the session
  restarts.
- GNU coreutils and sed are on the path, not the macOS ones: use `sed -i`, not
  `sed -i ''`.
- `examples/` is a symlink, created by the dev shell, to real manuals pinned by
  `flake.lock` (texinfo, make, sed, gawk). It is not committed.

## Layout

- `grammar.js`: the grammar. Line commands and heading levels are listed here.
- `src/scanner.c`: external scanner. Holds the table of block names and kinds
  (block, list, raw, macro), the stack of open blocks that makes `@end NAME`
  match, raw block bodies, and the end-of-file token. Add new blocks here.
- `src/` (except `scanner.c`) is generated by `tree-sitter generate` and is
  committed; always commit it together with the `grammar.js` change.
- `test/corpus/*.txt`: corpus tests.
- `script/compare-texi2any.py`: compares our trees with texi2any's.

## Checks

A Claude Code hook (`.claude/hooks/check-grammar.sh`) runs `tree-sitter
generate` and `tree-sitter test` after every edit to `grammar.js`,
`src/scanner.c` or the corpus. Before committing grammar or scanner changes,
also run:

```sh
tree-sitter fuzz --iterations 100        # incremental parsing after edits
tree-sitter parse --quiet --stat 'examples/**/*.texi'
find -L examples -name '*.texi' | sort | xargs python3 script/compare-texi2any.py
```

Known noise in the comparison: `gawk-5.4.1/it/gawk.texi` and
`texinfo-7.3/texinfo-tex-test.texi` (texi2any fails on them),
`html_default_commands_args.texi` (a fragment for `@include`), and the Italian
`pm-gawk.texi` (uses a macro before defining it). Use `--structure` to compare
only blocks, items and line commands.

## Conventions

- Commit messages follow Conventional Commits (`feat:`, `fix:`, `test:`,
  `build:`, `docs:`, `chore:`).
- Test first: for new behaviour, write the corpus test with its expected tree
  by hand, based on what texi2any does, and see it fail before changing the
  grammar. Use `tree-sitter test --update` only to regenerate existing tests
  after a deliberate change to the tree's shape, and read every regenerated
  tree before keeping it.
- A corpus test's input starts right after the header line, so a blank line
  there is part of the input.
- Mark tests that must produce a parse error with `:error` under the title.
- Don't check the column in the scanner: tree-sitter does not re-scan a token
  when text before it on the same line changes. Keep line-start rules in the
  grammar (every line-level rule ends in `_line_end`).
- Update `TODO.md` in the same commit as the work it tracks.
